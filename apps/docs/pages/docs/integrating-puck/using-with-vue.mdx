# Using with Vue

Use the full Puck editor and `<Render>` in a [Vue 3](https://vuejs.org/) app,
with **Vue components as your Puck components** — no React dependency in your
app, and no framework rewrite of Puck.

This is provided by the [`@puckeditor/vue`](https://www.npmjs.com/package/@puckeditor/vue)
package. Internally it compiles `@puckeditor/core` against
[Preact](https://preactjs.com/) and bundles Preact inside the package as an
implementation detail — you never install or import React or Preact yourself.

## Installation

```sh copy
npm i @puckeditor/vue vue
```

`vue` (`^3.3`) is a peer dependency. That's it — no `react` or `react-dom`.

## Quick start

Define a `VueConfig` — identical to a core `Config`, except each component's
`render` is a **Vue component**:

```ts copy showLineNumbers filename="puck.config.ts"
import type { VueConfig } from "@puckeditor/vue";
import Heading from "./components/Heading.vue";

export const config: VueConfig = {
  components: {
    Heading: {
      fields: { title: { type: "text" } },
      defaultProps: { title: "Hello" },
      render: Heading,
    },
  },
};
```

```vue copy filename="components/Heading.vue"
<script setup lang="ts">
defineProps<{ title?: string }>();
</script>

<template>
  <h1>{{ title }}</h1>
</template>
```

Render the editor with `<Puck>` and the published page with `<Render>`:

```vue copy filename="Editor.vue"
<script setup lang="ts">
import { Puck } from "@puckeditor/vue";
import "@puckeditor/vue/puck.css";
import { config } from "./puck.config";

const data = { root: {}, content: [] };
function onPublish(data: unknown) {
  /* persist data */
}
</script>

<template>
  <div style="height: 100vh">
    <Puck :config="config" :data="data" @publish="onPublish" />
  </div>
</template>
```

```vue copy filename="Page.vue"
<script setup lang="ts">
import { Render } from "@puckeditor/vue";
import "@puckeditor/vue/puck.css";
import { config } from "./puck.config";

const data = {
  /* your published data */
};
</script>

<template>
  <Render :config="config" :data="data" />
</template>
```

Everything else in `Config` — `fields`, `defaultProps`, `resolveData`,
`resolveFields`, `resolvePermissions`, `categories`, `label` — is
framework-agnostic and works exactly as documented for
[`@puckeditor/core`](/docs/api-reference/configuration/config).

## `<Puck>` props and events

`<Puck>` accepts `config`, `data`, and the passthrough props `permissions`,
`viewports`, `iframe`, `dnd`, `metadata`, `headerTitle`, `headerPath`,
`height`, `fieldTransforms`, plus the initial-only `ui` and `initialHistory`,
and these events:

| Event          | Payload                                                        |
| -------------- | -------------------------------------------------------------- |
| `@change`      | the current data (on every edit)                               |
| `@update:data` | the current data (alongside `@change`, for `v-model:data`)     |
| `@publish`     | the current data (on publish)                                  |
| `@action`      | `(action, appState, prevAppState)` on every dispatched action  |
| `@ready`       | a `getPuck` accessor — call `getPuck()` for the `PuckApi`      |

```vue copy
<Puck
  :config="config"
  v-model:data="page"
  @publish="onPublish"
  @ready="(getPuck) => (myGetPuck = getPuck)"
/>
```

As with React, `data` is **initial-only** — inbound changes after mount do not
reset the editor (`v-model:data` keeps your binding up to date outbound).
Changing `config` identity is a full remount.

## Slots and DropZones

For a [slot field](/docs/integrating-puck/multi-column-layouts), render the slot
prop in your template with `<component :is>`:

```ts copy
// config
Columns: {
  fields: { items: { type: "slot" } },
  render: Columns,
},
```

```vue copy filename="Columns.vue"
<script setup lang="ts">
import type { VueSlot } from "@puckeditor/vue";
defineProps<{ items?: VueSlot }>();
</script>

<template>
  <div class="columns">
    <component :is="items" />
  </div>
</template>
```

You can pass DropZone props as attributes, e.g.
`<component :is="items" :allow="['Heading']" />`.

The same pattern renders every *node-valued* field — `richtext` fields and
`contentEditable` text fields also arrive as `VueSlot` outlet components
(an inline editor in `<Puck>`, static content in `<Render>`):

```vue copy
<h1><component :is="title" /></h1>
```

## Custom fields

Set a field to `{ type: "custom", render: MyVueField }`. The field render props
(`id`, `name`, `value`, `onChange`, `field`, `readOnly`) arrive as plain props,
and the idiomatic `v-model` contract is also provided (`modelValue` +
`update:modelValue`), so `defineModel()` just works:

```vue copy filename="TextField.vue"
<script setup lang="ts">
const model = defineModel<string>();
</script>

<template>
  <input v-model="model" />
</template>
```

Alternatively call `onChange` directly. Use the exported `FieldLabel` for a
native-looking label:

```vue copy filename="ColorField.vue"
<script setup lang="ts">
import { FieldLabel } from "@puckeditor/vue";
defineProps<{
  name?: string;
  value?: string;
  field?: { label?: string };
  readOnly?: boolean;
  onChange: (value: string) => void;
}>();
</script>

<template>
  <FieldLabel :label="field?.label || name || ''" :read-only="readOnly">
    <input
      type="color"
      :value="value"
      @input="onChange(($event.target as HTMLInputElement).value)"
    />
  </FieldLabel>
</template>
```

To replace a built-in field UI globally, pass a `fieldTypes` map to `<Puck>`:

```vue copy
<Puck :config="config" :data="data" :field-types="{ text: MyTextField }" />
```

## Sharing Pinia, plugins and global components

Bridged Vue components automatically inherit the app context of the app
rendering `<Puck>` / `<Render>` — Pinia stores, plugins, app-level `provide`s
and globally-registered components just work, with no setup.

To substitute a *different* context (e.g. to isolate the editor preview from
your app), create an unmounted app instance carrying the plugins and pass it
via the `app` prop (read once at setup):

```ts copy
import { createApp } from "vue";
import { pinia } from "./store";

const bridgeApp = createApp({});
bridgeApp.use(pinia);
```

```vue copy
<Puck :config="config" :data="data" :app="bridgeApp" />
```

## The `usePuck` and `usePuckApi` composables

Inside a bridged component, `usePuck()` returns the reactive per-component Puck
context (`isEditing`, `metadata`, `renderDropZone`, `id`):

```vue copy
<script setup lang="ts">
import { usePuck } from "@puckeditor/vue";
const puck = usePuck();
</script>

<template>
  <span v-if="puck.isEditing">Editing…</span>
</template>
```

To *reactively subscribe* to editor state — the equivalent of React's
selector-based [`usePuck`](/docs/api-reference/puck-api) — use
`usePuckApi(selector)` from a bridged component or custom field. It returns a
ref that updates whenever the selected value changes:

```vue copy
<script setup lang="ts">
import { usePuckApi } from "@puckeditor/vue";

const selectedItem = usePuckApi((api) => api.selectedItem);
const hasPast = usePuckApi((api) => api.history.hasPast);
</script>
```

For one-shot imperative control, use the `getPuck` accessor from `@ready` — it
returns the same [`PuckApi`](/docs/api-reference/puck-api).

## Mixed React/Vue configs

If you have an existing React config and want to add a few Vue components, use
the escape hatches instead of `transformConfig`:

- `defineVueComponent(MyVueComponent)` → a component `render`
- `defineVueField(MyVueField)` → a custom field `render`

```ts copy
import { defineVueComponent } from "@puckeditor/vue";

const config = {
  components: {
    MyReactComponent: {
      /* ... */
    },
    MyVueComponent: {
      fields: {
        /* ... */
      },
      render: defineVueComponent(VueHeading),
    },
  },
};
```

## Styling

Import the styles once, exactly as with core:

```ts copy
import "@puckeditor/vue/puck.css";
```

Single-File Component `<style scoped>` styles work in the editor preview with no
extra setup — Vite injects them into the document head and Puck's iframe mirrors
head styles into the preview.

## Limitations

- Advanced `overrides` / `plugins` are passed through as Preact components (for
  advanced users); Vue equivalents are not yet available.
- `<Render>` mounts client-side (the server emits an empty div) — no SSR/SSG
  output for published pages yet.
- Rich text / `contentEditable` fields nested inside `object`/`array` fields
  are not supported (top-level fields only).
