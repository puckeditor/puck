# CLI

The Puck CLI sets up Puck and [Puck Cloud](https://cloud.puckeditor.com) in a new or existing app. It's built for coding agents, and works interactively for humans.

```sh copy
npx @puckeditor/cli init
```

`init` inspects your project and makes the smallest set of changes needed to reach a working Puck app, with Puck AI if you choose it:

- **No app yet**: creates a Next.js, React Router, TanStack Start, vinext, Vite or Astro app, or a Hono or Express server, from the Puck [recipes](https://github.com/puckeditor/puck#recipes)
- **App without Puck**: installs `@puckeditor/core` and adds an editor at `/edit`
- **Puck without Puck AI** (when you choose it): installs `@puckeditor/cloud-client` and `@puckeditor/plugin-ai`, adds the `/api/puck` route and the Puck AI plugin, and connects your Puck Cloud account
- **Already set up**: verifies the setup and changes nothing

With Puck AI, the only manual step is logging in to Puck Cloud and approving the connection in your browser. When it's done, the CLI starts your dev server and opens the editor.

Puck AI is optional. It's the editor plugin that uses Puck Cloud as its backend, so choosing it sets up Puck Cloud too. `init` asks whether to add it; pass `--ai` or `--no-ai` to choose up front.

## Supported projects

- Next.js 15+ using the App Router (`app/` or `src/app/`)
- React Router 7+ in framework mode. New apps use React Router 8, or React Router 7 on Node.js older than 22.22, which React Router 8 requires
- [TanStack Start](https://tanstack.com/start) 1.132+
- [vinext](https://github.com/cloudflare/vinext) 1+ using the App Router
- [Vite](https://vite.dev) 6+ React apps (see [Vite and Astro](#vite-and-astro))
- [Astro](https://astro.build) 7+ (see [Vite and Astro](#vite-and-astro))
- [Hono](https://hono.dev) 4+ and [Express](https://expressjs.com) 4.16+ servers (see [Servers](#servers))
- npm, pnpm, Yarn and Bun, including workspaces
- TypeScript projects

Run `npx @puckeditor/cli frameworks` to see what the CLI sets up for each framework. Older versions fail with `PUCK-CLI-UNSUPPORTED-FRAMEWORK-VERSION`.

When the CLI can't safely change something, like an existing `middleware.ts`, it leaves the file alone and tells you exactly what to add.

## Vite and Astro

A Vite app, or an Astro site without a server adapter, has nowhere to save pages or run Puck Cloud. The CLI asks where that server comes from. Agents get a `choose_backend` action; pass `--backend` to choose up front:

- `--backend add`: in Vite, adds a Hono server in `server/`, run by Vite in development with `@hono/vite-dev-server` and by `npm start` in production. In Astro, runs `astro add node` so pages and API routes are served on demand
- `--backend external --backend-url <url>`: proxies `/api` to a server that runs elsewhere, e.g. a [Hono or Express server](#servers) set up by the CLI. Puck Cloud and `PUCK_API_KEY` live on that server
- `--backend none`: saves pages in the browser's `localStorage`. Puck AI isn't available without a server

In Vite, the editor opens at any URL ending in `/edit`: `<PuckRoot>` wraps your app in `src/main.tsx` and renders the editor instead. Render published pages with `<PuckPage path={...} />` wherever your app renders pages.

In Astro with an adapter, `src/pages/[...puckPath].astro` renders the editor at `/edit` URLs and published pages everywhere else, on the server. Without one, the editor is a static page at `/edit?path=/your/page`. The CLI runs `astro add react` when React isn't set up yet.

## Servers

In a Hono or Express project, the CLI sets up the APIs a Puck editor in another app talks to:

- `/api/pages`: loads (`GET ?path=/about`) and saves (`POST { path, data }`) pages, in `src/puck/pages.ts`
- `/api/puck/*`: the Puck Cloud route for Puck AI, in `src/puck/cloud.ts`, when you choose Puck AI

With [Puck Pages](#puck-pages), `/api/pages` serves pages published in Puck Cloud instead, and only loads them.

It mounts both on your app before it starts serving, so your own middleware runs first. Node doesn't load `.env` files, so the CLI adds `--env-file-if-exists=.env.local` to a `tsx` or `node` dev script. Bun loads `.env.local` itself. On Cloudflare Workers, put `PUCK_API_KEY` in `.dev.vars` instead.

Add the Puck AI plugin in the app with the editor. If that app runs on another origin, proxy `/api` to the server in development, or pass `host` to `createAiPlugin`.

## For coding agents

Run with `--yes --json`. The CLI never prompts, and prints exactly one JSON document to stdout.

```sh copy
npx @puckeditor/cli init --yes --json
```

When `status` is `action_required`, nothing has been changed yet. Show each entry in `actions` to the developer, then run its `rerun` command. Without `--ai` or `--no-ai`, the first run returns a `choose_ai` action, so the developer can decide whether to add Puck AI. With `--ai`, the first run asks the developer to log in:

```json
{
  "status": "action_required",
  "message": "Puck Cloud login required. No changes have been made yet.",
  "actions": [
    {
      "type": "browser_login",
      "url": "https://cloud.puckeditor.com/cli/connect#code=BCDF-GHJK",
      "userCode": "BCDF-GHJK",
      "rerun": "npx @puckeditor/cli init --yes --json --ai"
    }
  ]
}
```

After the developer approves, the same command completes the setup:

```json
{
  "status": "success",
  "project": { "framework": "next", "packageManager": "pnpm" },
  "puck": { "installed": true, "configured": true },
  "cloud": { "configured": true, "verified": "remote" },
  "ai": { "installed": true, "configured": true },
  "filesModified": [".env.local", "app/api/puck/[...all]/route.ts"]
}
```

Start with `npx @puckeditor/cli status --json` to see what's already set up and which command to run next.

### Statuses

| Status            | Meaning                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------- |
| `success`         | The project is set up. `changed` is `false` if there was nothing to do.                 |
| `action_required` | Input or approval is needed. Nothing was changed. Complete `actions`, then run `rerun`. |
| `partial`         | Changes were applied, but some `actions` must be completed by hand.                     |
| `error`           | Something went wrong. See `error.code` and `error.message`.                             |

### Actions

| Type                       | What to do                                                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `browser_login`            | Ask the developer to open `url`, confirm `userCode` and approve                                                                      |
| `provide_api_key`          | Ask for a Puck API key, then re-run with `PUCK_API_KEY` set                                                                          |
| `confirm_plan`             | Review `plan.steps`, then re-run with `--yes`                                                                                        |
| `choose_ai`                | Ask the developer, then re-run `init` with `--ai` or `--no-ai`                                                                       |
| `choose_backend`           | Ask the developer, then re-run with `--backend add`, `--backend external --backend-url <url>` or `--backend none`                    |
| `choose_framework`         | Re-run `init` with `--framework` and one of `next`, `react-router`, `tanstack-start`, `vinext`, `vite`, `astro`, `hono` or `express` |
| `provide_app_name`         | Re-run `init` with `--name <name>`                                                                                                   |
| `choose_workspace_package` | Re-run with `--workspace <dir>` for one of `choices`                                                                                 |
| `manual_edit`              | Apply `snippet` to `file` as described in `instructions`                                                                             |
| `set_environment_variable` | Set `PUCK_API_KEY` wherever the app runs                                                                                             |

### Exit codes

| Code | Meaning                                         |
| ---- | ----------------------------------------------- |
| 0    | Success                                         |
| 2    | Invalid arguments or API key                    |
| 3    | Unsupported or ambiguous project                |
| 4    | File conflict                                   |
| 5    | Package manager failure                         |
| 6    | `doctor` found problems                         |
| 7    | Puck Cloud couldn't complete a login or request |
| 10   | Action required                                 |
| 11   | Partially set up                                |

### Reading the docs

The CLI includes these docs as markdown, matching its release. Use the version of the CLI that matches the project's `@puckeditor/core`:

```sh copy
npx @puckeditor/cli docs ls                          # every page
npx @puckeditor/cli docs find "dynamic fields"       # find pages by title or heading
npx @puckeditor/cli docs grep resolveData            # search page content
npx @puckeditor/cli docs cat api-reference/fields/text
```

The latest docs are indexed at [llms.txt](https://puckeditor.com/llms.txt), and any page is available as markdown by adding `.md` to its URL. Agents with skill support can also install the [Puck skill](https://github.com/puckeditor/skills):

```sh copy
npx skills add puckeditor/skills --skill puck
```

## Commands

| Command               | Description                                                             |
| --------------------- | ----------------------------------------------------------------------- |
| `init`                | Set up Puck, optionally with Puck AI, creating an app if needed         |
| `add editor`          | Add the Puck editor                                                     |
| `add cloud`           | Connect Puck Cloud (adds the editor first if needed)                    |
| `add ai`              | Add the Puck AI plugin (adds Puck Cloud first if needed)                |
| `add pages`           | Store and publish pages in Puck Cloud (adds Puck Cloud first if needed) |
| `add auth`            | Require Sign in with Puck to edit (adds Puck Cloud first if needed)     |
| `pages import <file>` | Publish pages from a JSON file to Puck Cloud                            |
| `connect`             | Log in to Puck Cloud again and replace `PUCK_API_KEY`                   |
| `status`              | Show what's installed and configured                                    |
| `doctor`              | Diagnose problems and suggest fixes. Never makes changes                |
| `frameworks`          | Show the supported frameworks and versions                              |
| `docs`                | Read these docs: `ls`, `cat <page>`, `find <query>`, `grep <text>`      |
| `telemetry`           | Show or change anonymous usage data collection                          |

## Flags

| Flag                       | Description                                                                                                       |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `--json`                   | Machine-readable output                                                                                           |
| `--yes`, `-y`              | Apply the plan without prompting                                                                                  |
| `--dry-run`                | Show the plan without changing anything or logging in                                                             |
| `--cwd <path>`             | Run against another directory                                                                                     |
| `--workspace <name\|dir>`  | Choose an app when running from a monorepo root                                                                   |
| `--api-key <key>`          | Use an existing API key instead of logging in                                                                     |
| `--no-env-write`           | Don't write `PUCK_API_KEY` to a file                                                                              |
| `--ai`                     | Also set up Puck AI and Puck Cloud (`init`)                                                                       |
| `--no-ai`                  | Set up the editor only, without asking about Puck AI (`init`)                                                     |
| `--pages`                  | Also set up [Puck Pages](#puck-pages) (`init`)                                                                    |
| `--auth`                   | Also set up [Puck Auth](#puck-auth) (`init`)                                                                      |
| `--backend <choice>`       | Where a Vite app's server comes from: `add`, `external` or `none`                                                 |
| `--backend-url <url>`      | The server for `--backend external`                                                                               |
| `--wait`                   | Wait for login approval instead of returning `action_required`                                                    |
| `--framework <name>`       | Framework for a new app: `next`, `react-router`, `tanstack-start`, `vinext`, `vite`, `astro`, `hono` or `express` |
| `--name <name>`            | Directory for a new app                                                                                           |
| `--package-manager <name>` | Override the detected package manager                                                                             |
| `--offline`                | Skip the Puck Cloud connection check (`doctor`)                                                                   |

## API keys

The CLI writes `PUCK_API_KEY` to `.env.local`, and makes sure it's ignored by git. If a key already exists in `.env.development.local`, it's updated there instead. Keys are never written to `.env`, and never printed.

To use an existing key, prefer the environment over `--api-key`, which is visible in your shell history:

```sh copy
PUCK_API_KEY=your-key npx @puckeditor/cli add cloud --yes
```

To log in again, for example to replace a revoked key, run `connect`. It always starts a new login and replaces the existing key, without changing any code:

```sh copy
npx @puckeditor/cli connect
```

Remember to set `PUCK_API_KEY` in your production environment too. `react-router-serve` and Cloudflare Workers don't load `.env` files; on Workers, use `wrangler secret put PUCK_API_KEY`.

The `/api/puck` route and the editor are public by default. Add [Puck Auth](#puck-auth), or your own authentication, before deploying.

## Puck AI

`init` and `add ai` add the Puck AI plugin to the editor, allow design mode in the `/api/puck` route, and wrap your config with `withDynamicConfig` so components designed by Puck AI render on your pages. If your editor has been customised, the CLI leaves it alone and prints the code to add.

## Puck Pages

`add pages`, or `init --pages`, stores pages in Puck Cloud with the [Pages plugin](https://puckeditor.com/docs/pages/overview), which adds page management, drafts, publishing and version history to the editor:

- The editor opens at `/puck`, with the page to edit in the `path` query parameter, e.g. `/puck?path=/about`. URLs ending in `/edit` redirect there
- Published pages are rendered from Puck Cloud with `getPage` from `@puckeditor/cloud-client`. In Vite apps and on [servers](#servers), `/api/pages` serves them read-only
- `@puckeditor/cloud-client` is updated to a version with Puck Pages, and the `/api/puck` route gets the `authenticate` option it requires

Pages in `database.json`, or wherever your app saved them, aren't moved automatically. Import them with `pages import`, then delete the old routes.

Until you add [Puck Auth](#puck-auth), anyone who can reach `/api/puck` can edit, publish and delete pages using your API key.

### Importing pages

```sh copy
npx @puckeditor/cli pages import database.json
```

`pages import` publishes a JSON object of Puck data keyed by route, like a recipe's `database.json`. Pages that already exist in Puck Cloud are kept. It uses `--api-key`, `PUCK_API_KEY` in the environment, or the key in the env files where it runs, so run it from your app. The API key decides which project and branch the pages go to.

Agents pass `--yes --json`. If Puck Cloud fails part way, the status is `partial` and `pagesImport.notImported` lists the routes left. Run the command again to import them.

## Puck Auth

`add auth`, or `init --auth`, requires [Sign in with Puck](https://puckeditor.com/docs/auth/overview) to edit:

- The `/api/puck` route passes `authenticate` from `@puckeditor/cloud-client/auth` to `puckHandler`, which serves the sign-in routes under `/api/puck/auth` and rejects requests from anyone not signed in to your Puck Cloud organization
- The editor sends signed-out visitors to sign in. Server-rendered apps check before rendering it. Vite apps, and Astro sites without a server, check in the browser with `<RequireSession>`
- The Puck Auth plugin adds an account menu to the editor

Without Puck Pages, the editor still saves pages through your own route, which Sign in with Puck doesn't protect. On a Hono or Express server, `add auth` only changes the Cloud route, so run it in the editor's app too.

Members sign in to the API key's project and edit its branch. Set `PUCK_API_KEY` on each deployment to a key for the branch it should edit, so a preview deployment can't edit production.

## Telemetry

The CLI collects anonymous usage data to help us improve it. The first time it runs without `--json`, it prints a notice.

Each command sends one event to Puck Cloud with:

- The command, what `add` was asked for, the result status, error and warning codes, the actions it returned, the exit code and how long it took
- Whether it was a dry run, made changes, ran interactively, used `--json` or ran in CI
- The CLI version, operating system, CPU architecture and Node.js version
- The name of the coding agent running it, if it's a known one, such as `claude-code`
- The framework and its major version, the package manager, the `--backend` choice, whether the project is in a monorepo, and whether the Puck editor, Puck Cloud and Puck AI are set up
- A random ID, stored in `~/.config/puck/telemetry.json`

It never sends code, file paths, project or package names, hostnames, error messages, flag values or API keys. When you log in to Puck Cloud with `connect`, the random ID is linked to your account.

To turn telemetry off, run:

```sh copy
npx @puckeditor/cli telemetry disable
```

Or set `PUCK_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1` in your environment. `telemetry status` shows whether it's on, and `PUCK_TELEMETRY_DEBUG=1` prints each event instead of sending it.
