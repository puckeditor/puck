# Internal Puck API

Puck exposes its internal API as [`PuckApi`](/docs/editor/api-reference/puck-api) for extending Puck with custom functionality within [custom fields](/docs/editor/components-and-fields/custom-fields), [compositional interfaces](/docs/editor/customize/composition), [UI overrides](/docs/editor/customize/ui-overrides) or [`renderFields`](/docs/editor/api-reference/configuration/component-config#renderfieldsprops).

## Accessing the internal API

You can access [`PuckApi`](/docs/editor/api-reference/puck-api) via two hooks:

- [`usePuck`](/docs/editor/api-reference/functions/use-puck) - returns `PuckApi` as part of your component render lifecycle
- [`useGetPuck`](/docs/editor/api-reference/functions/use-get-puck) - returns a function to access the latest `PuckApi` at call time

### Within the render lifecycle

To access the API within your render lifecycle, use the `usePuck` hook. You can use a selector to limit re-rendering to a specific part of the API.

```tsx copy
import { createUsePuck } from "@puckeditor/core";

const usePuck = createUsePuck();

const Example = () => {
  // Use a selector so you only re-render when the selected type changes
  const type = usePuck((s) => s.selectedItem?.type || "Nothing");

  return <h2>{type} selected</h2>;
};
```

See the [`usePuck`](/docs/editor/api-reference/functions/use-puck) docs for a full API reference.

### Outside of the render lifecycle

Often it's not necessary to re-render your component when the PuckApi changes. Puck provides the `useGetPuck` hook for accessing the latest `PuckApi` at call time.

```tsx copy
import { useGetPuck } from "@puckeditor/core";

const Example = () => {
  const getPuck = useGetPuck();

  const handleClick = useCallback(() => {
    // Get the latest PuckApi value
    const { appState } = getPuck();

    console.log(appState);
  }, [getPuck]);

  return <button onClick={handleClick}>Click me</button>;
};
```

See the [`useGetPuck`](/docs/editor/api-reference/functions/use-get-puck) docs for a full API reference.

## Usage in practice

Generally, you'll want to combine this with composition, UI overrides, custom fields or [`renderFields`](/docs/editor/api-reference/configuration/component-config#renderfieldsprops).

Here's an example using the internal API to log the page data as JSON while retaining the standard Puck UI:

```tsx
import { Puck, createUsePuck } from "@puckeditor/core";

const usePuck = createUsePuck();

const JSONLogger = ({ children }) => {
  const appState = usePuck((s) => s.appState);

  useEffect(() => {
    console.log(appState);
  }, [appState]);

  return <>{children}</>;
};

export function Editor() {
  return (
    // Render the Puck context
    <Puck>
      <JSONLogger>
        {/* Since we're overriding Puck's children, we restore the standard Puck UI */}
        <Puck.Layout />
      </JSONLogger>
    </Puck>
  );
}
```
